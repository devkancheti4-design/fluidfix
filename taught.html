fluidfix · measured 18 september 2026

A taught class is a regex and a function.

That is the whole mechanism. It is not a model, not a table of past fixes, and not trained. Four of them repaired 240 bugs none of them had ever seen — while a table that stores one row per repair needed 146 rows to reach 28%.

the mechanism

Two halves, and neither is trusted

A class says which lines could possibly have this fault and what to try instead. Nothing else. Here is a real one, written from a bug a 4-billion-parameter model actually wrote:

# The fault: a collection is mutated in place on the last line and never returned,
# so the caller gets None.  items.insert(index, value)  ->  the caller wanted `items`.

def _return_the_mutated(line, o):
    m = re.match(r"^(\s*)([A-Za-z_]\w*)\.(\w+)\((.*)\)\s*$", line)
    if not m:
        return []
    indent, receiver, _meth, _args = m.groups()
    return [f"{indent}return {line.strip()} or {receiver}"]

register(4, "mutating-call-whose-result-is-dropped",
         "mutated in place on the last line and never returned",
         re.compile(r"^\s*[A-Za-z_]\w*\.\w+\(.*\)\s*$"),   # the signal
         _return_the_mutated)                        # the applier

The signal

A regex. It says only that this line could exhibit the fault, so the search knows which lines are worth a candidate at all.

The applier

Proposes replacement lines. It may propose several, or none. It never decides anything.

The judge

Your test suite, and only your test suite. A candidate is kept because the tests went green; every rejected one is rolled back byte-exact.

Because the applier derives the fix from the line in front of it, a class is not bound to the line it was taught from. That is the difference between this and a cache, and it is measurable.

the measurement

240 bugs, every one of them unseen

Eight fault shapes, 30 instances each, and every instance distinct — its own function name, its own variables, its own literals, its own surrounding code. Each carries a test that catches it, verified to fail first. Two arms face the same stream: the vocabulary, and a line table that stores the exact broken line against the exact fixed line and may only replay what it stored.

The vocabulary stays four. The table grew to 146 rows and still lost by 72 points, because the exact lines almost never recur.

Two of those four classes were written the same afternoon, from faults real models had actually produced — and they behaved exactly like the ones taught by hand a fortnight earlier. Knowledge pulled out of one incident transfers to code nobody has seen.

where a class comes from

You do not invent them. The search names them.

For a red test, it tries the free vocabulary first and widens the budget only when the tests reject everything — one line, then adding a line, then a rewrite. The first budget that passes is the fault's kind, so no one has to judge it. Over fourteen bugs small models actually wrote:

A shape earns a slot only when it recurs. Two of the eleven appeared twice each, in code written by different models — those two were written up as classes, and the free tier went from 1 of 14 to 5 of 14, at zero tokens.

what is not settled

We need to scan real repositories

Everything above is about behaviour within a shape, and there it is complete: the vocabulary generalises, the curve rises, the table does not keep up. The question it cannot answer is the one that decides how much of the work a model still has to do.

100% means 100% of bugs whose shape is taught.

Every bug in that corpus is one of eight shapes we chose, so the open-ended faults — the ones a model must still write — are absent by construction. What fraction of a real codebase's incidents fall into teachable shapes cannot be measured from a corpus we built ourselves.

The nearest real figure is much weaker and we would not quote it: on four open-source repositories, 22 of 38 live breaks fell inside the taught vocabulary. Those were seeded faults, of shapes chosen in advance — not a team's actual incident history.

So the next measurement is not another benchmark. It is a real repository: point it at a CI in report-only mode, take a week of failures, and let the budget ladder sort them into kinds. That produces the one number nothing here can — the shape distribution of incidents that actually happen — and with it, how many classes an afternoon of teaching would be worth.
