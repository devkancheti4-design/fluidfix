## design note (user, 23:xx): "many fluidfix through the repo, one fluidfix on all of them again"
- Shard a big repo into territories (package / file / line range), one guard per shard in its OWN working copy, all in parallel; a single top-level guard does no search of its own: it judges the shards' greens and refusals with the same laws — one green program ships, two different programs (differential probe across shards) refuse as AMB, none refuses with every shard's reason. Byte-exact rollback per shard; suite still the only judge. What it buys, from today's cost map: the per-file coverage passes and the full-sight uniqueness pass over huge files become parallel; what it does not buy: a wrong pointer (doctest → __init__.py) stays wrong.
